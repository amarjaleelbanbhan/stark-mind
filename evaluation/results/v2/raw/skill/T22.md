**Prompt:** Why does `git push` say 'rejected – non-fast-forward'? I need to push my fix.

---

`git push` rejects a **non-fast-forward** push when the remote branch has commits that your local branch doesn't have. Git won't let you overwrite history it hasn't seen — someone else (or another machine/branch of yours) pushed changes after you last pulled, so your local branch and the remote have diverged.

**To fix it and push your fix:**

1. **Pull and merge** (simplest, keeps both histories):
   ```
   git pull
   git push
   ```

2. **Pull and rebase** (cleaner history, puts your commit on top):
   ```
   git pull --rebase
   git push
   ```
   If there are conflicts, Git will pause and let you resolve them file by file, then `git rebase --continue`.

3. **Force push** (⚠️ only if you're 100% sure the remote commits can be discarded — e.g., you're the sole user of that branch or it's your own feature branch):
   ```
   git push --force
   ```
   Avoid this on shared branches like `main`/`master` — it can erase others' work.

Option 2 is usually the right call for a personal fix branch; option 1 if you don't mind a merge commit.
